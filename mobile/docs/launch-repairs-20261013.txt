SHARED OWNERSHIP
The server remains the owner of permissions, financial settlement, purchased
course entitlements, project results and certificate eligibility. Optional cache
work cannot hold an acknowledged result. Preparation belongs to an active visit;
already-dispatched work retains its account/domain owner and recovery identity.

NINE AUDITED REPAIRS
1 Product feature availability: concurrent bounded disk hydration and network
  refresh; optional serialized persistence no longer owns delivery.
2 Purchase entry: optional wallet/catalog reads do not own the paywall; direct
  exact-funding quotes bind the canonical cheapest rounded package rate once.
  Older unbound/native quote contracts still use explicit package authorization.
3 MyCorner: canonical courses publish independently of optional profile,
  streak and paths; account/read generations prevent older enrichment replacing
  a newer library.
4 Certificates: issued artifacts publish independently of new-issuance
  eligibility; issuance still requires both current successful server reads.
5 AI consent: server-confirmed consent is delivered independently of optional
  local receipt persistence; account-scoped serialization preserves revocation.
6 Section completion: confirmed completion is delivered before optional player
  cache/journal cleanup; required watch evidence and unacknowledged retry
  durability retain their original mandatory ordering.
7 Project result refresh: the optional player overlay starts alongside the
  server read and has a 250ms budget, matching the existing course loader.
  Local cache never grants server-locked access or overwrites a newer map.
8 Project actions: discussion, report retry and review retry use one shared
  preparation lease. Departure retires preparation and late consent UI; a
  dispatched request remains owned and cannot be replayed by reopening.
9 Late native credit: pending course upgrade observes the existing verified
  native and external credit buses and runs the same single-flight server
  reconciliation, without new payment or event-based enrollment grants.

CROSS-PLATFORM COURSE CHECKOUT
Both supported mobile platforms now request channel=direct and
funding_mode=exact_shortfall for a course purchase/upgrade. They use the same
signed rokn.app/course-payment URL, server-bound cash quote, existing Kashier
hosted page and receipt reconciliation. Android retains its Chrome-first native
launcher with default-browser fallback. iOS reuses React Native Linking.openURL
to hand HTTPS to the user's default browser; no auth session or WebView.
Listeners are installed before browser launch, cleaned on completion and handle
manual foreground return as reconciliation, not proof of cancellation/payment.
The existing cold-start durable return path and server receipt checks remain.

Grant-code entry is available on both platforms. Legacy native receipt recovery
and distribution-specific wallet compatibility remain; native paid-coin
settlement is not deleted just because new course intents use Kashier.
Apple sign-in remains an OS-specific platform integration, not a checkout fork.

Kashier's existing hosted integration is reused, not rewritten. Its published
customer list and thousands-of-merchants claim are adoption evidence from the
provider, not an independent uptime/performance audit.
https://developers.kashier.io/docs/accept-payments/payment-sessions
https://www.kashier.io/about

STORE PUBLICATION CONSTRAINT
As checked against official rules on 2026-10-13, an in-app button directing an
Egypt-storefront user to external payment for digital course access is not
automatically permitted. Apple 3.1.1(a) limits external-link exceptions by
storefront/entitlement; Google Payments sections 4, 8 and 9 require an applicable
exception/program. Grant-code unlocks also require accurate review disclosure.
No qualifying Egypt exception or entitlement has been established here.
These candidates implement the user-requested identical product; they are not
represented as compliant/approved store releases. No reviewer-specific bypass,
remote switch to conceal checkout, resubmission or publication is authorized
by this build record. Store approval is not proven by successful compilation.
https://developer.apple.com/app-store/review/guidelines/#business
https://support.google.com/googleplay/android-developer/answer/9858738?hl=en
